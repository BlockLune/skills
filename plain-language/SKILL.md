# 简明写作

按 `BLUF / Minto`、`Diátaxis`、`80% ASD-STE100` 与 `ISO 24495-1:2023` 写作或改写，让读者第一遍就读懂。

## 流程

1. 选定体裁与目标语言
   - 技术文档按 [diataxis.md](references/diataxis.md) 选定单一模式（教程、操作指南、参考、解释），一文一体裁。
   - Commit 与 PR 描述跳过 Diátaxis，先写问题与用户影响，再写修改原因；大段日志、提交列表或指标表改用链接。
   - 写中文时读取 [chinese.md](references/chinese.md)；写英文时读取 [english.md](references/english.md)；中英混排或双语对照时两者都读。
   - 有字数限制或需运行格式与中英混排检查时读取 [tools.md](references/tools.md)。

   **完成标准**：体裁明确，目标语言对应的参考文件已加载。

2. 组织结构与核对事实（BLUF / Minto）
   - 首段直接给核心结论，段首第一句点题，同层并列项归为同类，同一事实全文只写一次。
   - 开头交代适用范围与前提，首次出现的领域概念给定义，使文档脱离当前对话仍可独立读懂。
   - 保留全部事实、数字、前置条件、异常分支、代码示例，以及“可能/通常/至少/尽快/大多数”等限定词，保持原有的确定程度（改写后可比原文长）；信息缺失时追问或标明未知。

   **完成标准**：结论在前，事实与限定词零删减，目录树或计数等可生成断言已附生成命令，未覆盖、未验证和待决事项已单列。

3. 打磨词句与版式（STE）
   - 以代码库为词表：直接写真实符号、文件路径、参数、命令或报错原文，不用泛化描述或自造隐喻。
   - 单步负载：每句只含一条指令或一个想法；前置条件与警告写在动作步骤之前；用主动语态明确动作发出者，操作步骤用直接祈使句；同一概念与同一动作全文固定一词，指代不明时换回具体名词。
   - 节奏与自然度：长短句交替（短句落结论，长句带条件或后果），拆分含两个想法的句子，保留承载单一完整想法的长句；套用某条规则让句子生硬像机器时，换种写法或保持原样。
   - 克制使用 Markdown 标记：依靠分段、语序和标点符号呈现重点与层次，只在需要视觉锚点区分不同性质的内容时少量使用加粗或斜体，避免给列表项开头批量加粗；修订既有文档时保留原有强调风格。
   - 版式规范：标题从单个 `#` 连续递增（限一至三级），标题直接亮明要点（操作标题用动词短语，概念标题用名词短语）；并列项用 `-`，连续步骤用 `1.`，两列键值信息用 `- a: b` 列表；围栏代码块标注语言，图片配说明性 alt 文本，链接文字写明目标标题或简短描述。

   **完成标准**：直接输出正文，无寒暄、动作预告、文档自指、修改总结或规则声明；符合已加载的 [chinese.md](references/chinese.md)、[english.md](references/english.md)、[diataxis.md](references/diataxis.md) 与 [tools.md](references/tools.md)。
