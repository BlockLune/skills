# 中文简明写作与改写示例

## 词句与语法

- 直接用动词：写“清洗数据”，不用“进行/加以/作出/予以 + 动词”。
- 操作步骤：用编号列表（`1.`）、动词开头，前置条件与警告写在步骤前，删掉“请/您/用户需要”及“只需/简单/轻松”。
- 数字与范围：数字带单位，范围写清端点（写“大于 10 / 不小于 10”，不用含糊的“10 以上/以下”）；中英文、数字、版本号之间加一个半角空格（如 `使用 React 19 构建应用`）。
- 指代与术语：同一概念全文固定一词；“它/这/该”可能指向多个名词或指代整个分句时，直接重复具体名词。

## 清理套话（保留正当例外）

- “不是 A 而是 B / A 不重要，重要的是 B”：前半句无实际信息时删掉前半句，直接写事实；纠正真实技术误解、做概念对照或表达“不只 A 还 B”时保留。
- 三段式与凑词排比：不为了凑结构硬套“首先…其次…最后…”或强凑三个排比词；客观上恰好是三个真实步骤或并列项时保留。
- 段末拔高与黑话：段末写完事实即停，删掉“这说明/由此可见/这体现了……”等升华句；将“赋能/抓手/闭环/打法/水位/底座”换成具体动作或真实指标；“发现/检测到 N 个失效项”直接写“N 个失效项”。

## 对照示例

### 1. 清理过程旁白、文档自指与修改历史

| --- | --- | --- |

| 标题复述 | `## 性能` 后第一句写“性能非常重要。” | `## 性能` 后直接写“P99 延迟从 120 ms 降到 35 ms。” |
| 注释里的修改历史 | `// 原先遍历全表导致 O(n²)，现改为用哈希表查找` | `// 用哈希表将查找复杂度控制在 O(1)，避免大表退化为 O(n²)` |

### 2. 操作步骤（前置条件单列、编号动词开头、条件在动作前）

改写前：

> 在开始之前，您需要先确保已经安装了 Node.js 20 以上版本，之后可以通过在终端中执行 npm install 来进行依赖的安装，安装完成以后再运行 npm run dev，如果端口被占用的话可以在 .env 文件里面修改 PORT。

改写后：

> 前提：本机已安装 Node.js（版本不小于 20）。
>
> 1. 在终端运行 `npm install` 安装依赖。
> 2. 运行 `npm run dev` 启动服务。
> 3. 如果提示端口被占用，打开 `.env` 文件修改 `PORT` 的值。

### 4. 保留限定词与前置条件（不删减条件、不篡改断言强度）

改写前：

> 该估算方法在大多数常规流量下误差较小，但对于样本量少于 30 个且分布明显偏斜的数据，结果可能不太可靠，建议尽快补充采样。

错误改写（删掉了并列条件，并把“大多数/可能/尽快”改成了绝对说法）：

> 该估算方法误差很小。样本少于 30 个时结果不可靠，必须立即补充采样。

正确改写（语言简化，保留“大多数/少于 30 个/并且/可能/尽快”）：

> 这个估算方法在大多数常规流量下误差较小。
>
> 有一种情况例外：样本少于 30 个，并且分布明显偏斜。这时结果可能不可靠，建议尽快补充采样。
