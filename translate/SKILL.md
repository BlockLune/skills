# 翻译

## 流程

1. 确定翻译对象，按顺序裁决：
   1. 参数里明确给出的文本；
   2. 参数里明确的文件路径，多个路径逐个处理；
   3. 从上下文推断，比如上一条消息；
   4. 仍确定不了，问一个具体问题并列出候选，例如「要翻刚才那段报错，还是 README」。
   完成标准：锁定唯一一段要翻译的内容，或已把带候选的问题发给用户并停下等待。

2. 确定方向：默认译成中文；输入几乎全是中文时译成英文。
   完成标准：目标语言明确；混合语言的输入按主要语言判断。

3. 按「术语规则」和「文风」翻译全文。
   完成标准：从头到尾翻完，无截断、无跳段；同一个术语的处理方式全文一致。

4. 输出。
   - 会话文本：直接给译文，前面不加「以下是翻译」之类的帽子，也不附原文对照。
   - 文件：按「文件细则」落盘。
   完成标准：会话模式译文已完整贴出；文件模式已给出 `/tmp/translate/` 下的完整路径，以及沿用原文写法的术语列表。

## 术语规则

- 译成中文：专有名词首次出现写「中文译名（Original Term）」，之后只写中文。
- 有些词当成专有名词或者术语，不需要翻译也不用加括号：token 写 token，agent harness 写 agent harness。
- 译成英文：首次出现写英文并括注中文原词，如 Xuecheng (学城)，之后只写英文；中文特有概念拿不准英译时保留中文。

## 文风

- 同一句话有几种等价译法时，选最自然、最像人写的那种。
- 源文明确有的结构（列举、排比、总结句）忠实保留，翻译优先于改写。
- 硬性禁区（只在等价译法中用来排除）：段末总结句（「这说明」「由此可见」）、三段式（「首先…其次…最后…」）、升华句、提示语（「值得注意的是」）、报告腔（「本次」「综上所述」「整体而言」）、形式连接词（「从而」「进而」「基于此」）。

## 文件细则

- 明确支持 `.md` / `.txt`；其他纯文本先警告再尽力翻译；二进制和图片直接拒绝并说明原因。
- 结果写到 `/tmp/translate/<源文件名>.<目标语言后缀>`：`foo.md` → `/tmp/translate/foo.zh.md`，后缀用 `zh` / `en`；同名文件直接覆盖。
- 遵循源文件格式：代码块（含注释）、行内代码、frontmatter 原样保留；链接文字可译、URL 不动；标题层级、列表、表格、引用块的结构不变。
- 长文件分段顺序翻译、逐段追加写入；超过 3000 行先告知工作量再开工。
