# Simple UI polish

## 开始前

确认下面两项。任一项缺失，先问用户，再动手。

- 范围（哪些页面、组件或文件）
- 模式（直接修改，或只读报告）

只读报告对每条发现给出位置、问题、建议改法。修改模式完成后，单列未验证项（例如未在浏览器中看过的宽度）。

## 规则

逐条检查范围内的每个界面。

### 文案

1. 用空格、换行或层级分隔文案，不用中点 “·”；发现即移除。
2. 界面只放用户完成任务所需的文字；解释性描述会弄脏界面并占用注意力，发现即删。
3. 文案对准界面的目标人群：易懂、不过于口语、长短贴合功能场景，不冗余、不造词。
4. 重写菜单与功能文案时，持产品经理视角，依据《Don't Make Me Think》与《写给大家看的设计书》：用户一眼看懂，用日常说法，不用术语，名称 2–4 字，描述不超过 20 字。功能不改。输出“原文案 → 新文案”对照表。拿不准的先问用户。

### 视觉

5. 颜色应跟随一套仓库规范或直接取自 Radix UI Colors。如果是后者，按它的 12 级色阶用途规范选级（背景、交互态、边框、实心色、文字各有对应色阶）。
6. 元素与文字做光学对齐；嵌套圆角做同心处理（外圆角 = 内圆角 + 间距）。
7. 线条与边框用 0.5px。
8. 字号至多 4 种，最好 3 种，最小 12px。层级不够时，用字重、字色、间距拉开。
9. 圆角和阴影只用在功能需要处，数值贴合场景；卡片不带单侧彩色边线。

### 交互

10. 除非用户显式声明需要动画与过渡，否则能省则省；必须加时，用 ease-out，基准 250ms。
11. 减少需要用户判断才能继续的交互；必须出现时，放在用户本来就要做选择的位置。
12. 重新审视页面的功能和元素，按信息优先级排序，用有秩序的结构组织。

### 前端实现

13. 优先复用项目已有依赖；需要新增时选成熟库，组件源码可控，设计语言统一，同类依赖只保留一个。下面是一些供参考的、可选择的成熟库：
    - UI 库：`shadcn/ui`、`Nova` 等
    - 图标：`Lucide` 等
    - 动画：`Motion` 等
    - 布局：`react-resizable-panels` 等
    - 拖拽：`dnd-kit` 等
    - 状态管理：`Zustand` 等
