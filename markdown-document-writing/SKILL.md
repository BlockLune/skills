# Markdown 文档撰写

## 撰写与交付

按文档类型、读者、用途及用户的模板要求组织内容，只询问阻塞推进的缺失需求。需要 README、教程、报告或设计方案等结构起点时，参考 [文档模板](references/TEMPLATES.md)。

有字数限制时，按章节分配篇幅，并按 [工具参考](references/TOOLS.md#中文字符统计) 确定统计口径、检查结果。需要自动检查、格式化或修复中英混排空格时，先读取 [工具与安全规则](references/TOOLS.md)。

交付前核对用户的内容与模板要求、下列适用的风格规则，以及字数限制。未完成的检查或跳过的格式化须说明原因。

## Markdown 风格

- 标题：需要文档标题时使用一个 `#`，章节层级连续。优先使用一至三级，不建议四级，禁止五级及以上。
- 中英混排：中文与英文、数字、版本号、技术术语之间添加空格，例如 `使用 React 19 构建应用`。
- 列表：并列项用无序列表（`- foobar`），连续步骤用有序列表（`1. foobar`），同一章节内标记一致。
- 表格：用于对比或紧凑结构化数据；段落或列表更易读时优先使用它们。两列键值信息使用 `- a: b` 列表。
- 代码块：使用围栏，已知语言时标注语言。
- 图片：使用标准 Markdown 图片语法，尽量提供说明性的 alt 文本。
- 强调：修订时保留原有粗体、斜体风格；新建文档尽量使用普通文本。
