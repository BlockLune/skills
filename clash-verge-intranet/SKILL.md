# Clash Verge 企业内网配置

## 目标：内外网各走合适的路径

让企业目标正确解析、经办公网或企业 VPN 到达，同时保留原有公网代理能力。以用户的目标域名/业务命令和一个已知可用的公网目标建立基线，企业域名、DNS 和网段需有现场或文档依据。

## 模型：一次请求有五个独立问题

```text
应用请求 → 是否进入 Clash → 如何解析域名 → 选择出站 → 系统路由 → 服务
                 接管         DNS          分流       可达性
```

DNS 内还要区分“问谁”和“返回真实地址还是 fake-ip”。下表是定位模型，不是要求依次修改所有字段；已有正确行为保持不变。

| 问题 | 机制与目的 | 修改依据与验证 |
| --- | --- | --- |
| 请求是否进入 Clash？ | 应用/系统代理需应用配合；TUN 在网络层接管，减少这种依赖 | 先查实际请求路径；确需 TUN 时单独授权，并验证 VPN 兼容性 |
| 谁知道企业域名的地址？ | `nameserver-policy` 将指定域的查询交给企业 DNS | 先验证企业 DNS 可达且答案正确，再检查系统和应用实际采用的结果 |
| 应用应该得到什么地址？ | fake-ip 用合成地址保留域名映射；`fake-ip-filter` 可让选定域返回真实地址 | 仅在需要真实 IP 或存在兼容问题时排除，核对过滤模式和活动 fake-ip 范围 |
| 连接是否经远端代理？ | 域名/IP DIRECT 规则让 Clash 从本机连接目标 | 查看实际规则命中；域名不可用或按 IP 访问时，才补必要 IP 规则 |
| 本机能否到达目标？ | 办公网或企业 VPN 提供实际路由；DIRECT 本身不创建连接能力 | 检查目标与企业 DNS 的路由和端口，保留承载流量的隧道 |

TUN 不等于 fake-ip；排除 fake-ip 不等于 DIRECT；DIRECT 不等于绕过企业 VPN。若缺少内网可达路径，先恢复网络前提。

需要平台命令或故障判断线索时，读 [现场发现](references/discovery.md)。生成补丁时，读 [字段语义与校验](references/configuration.md)，特别核对规则优先级、过滤模式和 DIRECT 二次解析。

## 落地：让修复成为配置来源，而非临时结果

```text
订阅 + 持久化覆写 → 合成运行 YAML → 内核活动配置
```

找到当前内核版本、profile、合成顺序与列表合并方式。运行 YAML 是生成产物，订阅本体也可能被刷新覆盖；更新应用支持的持久化来源。

向用户说明“哪层失败 → 改哪个字段 → 如何证明修好”，附文件差异、影响、重载中断和失败回滚方案，取得授权后应用：

- 备份本次修改文件并保留权限，记录新建文件；备份放在本机受限位置。遇到并发改写重新合并，保留无关配置并去重。
- 用实际运行内核校验完整候选配置，通过后经已核实的入口重新生成、重载。无法离线合成时，先确认受控应用及即时回退方案。
- 核对最终配置与活动状态。保留无关 VPN、系统 DNS 和代理设置，隐藏订阅 URL、token、代理密码和控制密钥。

## 证明：现在可用，下次仍可用

复测实际应用解析、目标端口、用户业务、必要 IPv6/VPN 路径及公网对照；再通过应用重新生成配置并复测，证明持久化有效。联网刷新订阅另行确认。

新增回归按授权方案撤销本次持久化差异，重新生成、重载并验证基线，保留并发更新。报告修改位置、备份和验证证据；未执行项目及恢复失败明确标记，不以诊断 warning 清零代替业务成功。
