# 入口文件、硬约束与重复错误的修正位置

## 选择入口文件

已有 `CLAUDE.md` 或 `AGENTS.md` 时直接编辑已有的文件，两个文件都有时编辑 `AGENTS.md`；两个文件都没有时新建 `AGENTS.md`，无需询问用户。只有 `CLAUDE.md` 时保持原样，不迁移到 `AGENTS.md`。新建 `AGENTS.md` 后在汇报里提示：所使用的 agent 只读取 `CLAUDE.md` 时，可以新建一个只包含一行 `@AGENTS.md` 的 `CLAUDE.md`。

只在发现 monorepo 信号（例如 `pnpm-workspace.yaml`、`package.json` 的 `workspaces` 字段或多个带有独立 `src/` 的子包）时，才提示按照子目录拆分 `AGENTS.md`。

## 入口文件的内容

入口文件控制在 100 行以内，从入口文件出发，最多再跳转两次就能读到任何一份文档（入口文件 → 文档 → 参考资料），包含四项内容：

- 文档指针：每条写清“什么情况下读取这份文档”（包括领域术语表，如果已有术语文件则直接指向该文件）。
- 硬约束：安全边界、不可逆操作等任何情况下都不能违反的规则。
- 一行检查命令：使用一条命令运行全部类型检查、测试和 lint。
- 触发清单（见 [fact-ownership.md](fact-ownership.md) 的“触发清单”）与重复错误的修正位置表。

目录结构、脚本列表、依赖版本等直接从仓库文件或命令就能查到的信息，直接从仓库查询，不在入口文件重复列出。

## 硬约束的执行者

写在入口文件里的文字规则，agent 多数时候会遵守，但不保证每次都遵守。盘点时为每条硬约束标注执行者：权限规则、hook、lint，或“只有文字”。把标注为“只有文字”的硬约束列入差距报告；权限规则与 hook 留给用户配置。

## 重复错误的修正位置

在入口文件放置一张简短表格。同一类错误出现第二次时，按照表格把修正写入对应位置：

| 重复出现的问题 | 修正位置 |
| --- | --- |
| 缺少项目约定 | 修改入口文件 |
| 某类任务缺少固定步骤 | 编写 skill |
| 检查必须稳定执行 | 编写脚本或 hook |
| 某个动作必须拦截 | 设置权限规则 |
