# 入口文件、硬性规则与重复出错时的修正位置

## 选择入口文件

只有 `CLAUDE.md` 时直接改它，不迁移到 `AGENTS.md`；只有 `AGENTS.md` 或两者都有时，改 `AGENTS.md`。两者都没有时直接新建 `AGENTS.md`，不用问用户。

新建 `AGENTS.md` 后，在汇报里提示用户：如果用的 agent 只读 `CLAUDE.md`，可以再建一个只含 `@AGENTS.md` 一行的 `CLAUDE.md`。

如果仓库是 monorepo（例如有 `pnpm-workspace.yaml`、`package.json` 含 `workspaces` 字段，或多个带独立 `src/` 的子包），再提示按子目录拆分 `AGENTS.md`。

## 入口文件的内容

入口文件控制在 100 行以内。从入口文件最多跳转两层就能找到任意文档（入口文件 → 文档 → 参考资料）。入口文件包含四项内容：

- 文档索引：每条写清什么情况下读这份文档。仓库已有术语表时直接指向它；有 `docs/adr/` 时只指向当前生效的索引，不指向归档目录 `docs/adr/archive/`。
- 硬性规则：安全边界、不可逆操作等任何情况下都不能违反的规则。
- 一行检查命令：用一条命令跑完类型检查、测试和 lint。
- 文档更新清单（见 [fact-ownership.md](fact-ownership.md) 的“文档更新清单”）与重复出错时的修正位置表。

目录结构、脚本列表、依赖版本等能直接从仓库文件或命令查到的信息，不写进入口文件。

## 硬性规则的强制手段

仅靠入口文件里的文字提醒，agent 多数时候会遵守，但不能保证每次都遵守。盘点时为每条硬性规则标明强制手段：权限规则、hook、lint，或“仅文字”。把标为“仅文字”的条目放进盘点报告；权限规则与 hook 留给用户配置。

## 重复出错时的修正位置

在入口文件放一张简短对照表。同一类错误第二次出现时，按表把规则补到对应位置：

| 重复出现的问题 | 修正位置 |
| --- | --- |
| 缺少项目约定 | 修改入口文件 |
| 某类任务缺少固定步骤 | 编写 skill |
| 检查必须稳定执行 | 编写脚本或 hook |
| 某个动作必须拦截 | 设置权限规则 |
